# Архитектура

Обоснование границ, зафиксированных в [AGENTS.md](../AGENTS.md). Полное архитектурное решение и
модель угроз — в [docs/plans/projects-tree/00-overview.md](plans/projects-tree/00-overview.md);
здесь — то, что нужно объяснить сверх правил канона.

## Ядро не импортирует `vscode`

```
Правила (classification)  ──┐
                            ├──> Дерево узлов ──> Адаптер VS Code ──> TreeView / декорации / меню
Обход (discovery)         ──┘                          │
                                                       └──> Действия (actions) ──> окно / терминал / процесс
```

`packages/projects-tree/src/projects/**` — обход файловой системы, правила классификации и модель
действий. Это чистый TypeScript, тестируемый без запуска редактора: юнит-тесты подставляют
фейковую ФС, а не открывают VS Code. `packages/projects-tree/src/editor/**` — адаптер, который
превращает результат ядра в TreeView, декорации и команды; он меняется по причинам платформы
(новая версия API, другой способ рендера), а не по причинам предметной области.

Граница проведена так, а не иначе, ради этого разделения причин изменения. Если бы ядро знало про
`vscode.TreeItem`, любой рефакторинг тестов ядра требовал бы запускать `@vscode/test-cli`, а любое
изменение API редактора задевало бы правила классификации.

Проверка машинная: правило dependency-cruiser `no-vscode-in-core` роняет `pnpm check`, и у него
есть фикстура-нарушитель, которая обязана падать под `depcruise:negative` (пакет 01-B плана этапа
01). Ручная проверка «на глаз» не заменяет это правило — она разово верна и молча устаревает при
рефакторе конфига.

## Почему CLAUDE.md — симлинк, а не копия AGENTS.md

Оба файла — канон для агента, но под разными именами читаются разными инструментами (Claude Code
ищет `CLAUDE.md`, другие агентские среды — `AGENTS.md`). Копия расходится с оригиналом при первой
же правке одного из двух файлов и расхождение не диагностируется автоматически. Симлинк устраняет
класс дефекта целиком: второго файла с содержимым не существует.

### Поведение на Windows

Репозиторий публичный, и участники могут клонировать его на Windows. По умолчанию (без
`git config core.symlinks true` и без специально включённой поддержки symlink в самой ОС) Git на
Windows не создаёт файловую ссылку при чекауте: `CLAUDE.md` материализуется как обычный текстовый
файл, содержащий строку `AGENTS.md` — путь цели, а не её содержимое. Инструмент, ожидающий в
`CLAUDE.md` текст канона, получит вместо него имя файла.

Следствие для тех, кто настраивает клиента на такой машине: включить `core.symlinks` до чекаута
(`git config --global core.symlinks true`, на Windows дополнительно требуются права на создание
symlink — либо режим разработчика, либо запуск от администратора) и перевыполнить чекаут файла,
если он уже был получен как текст. Полагаться на «работает на моей машине» здесь нельзя — это
поведение зависит от ОС и конфигурации Git, а не от содержимого репозитория.
