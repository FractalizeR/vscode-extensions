# Этап 05. Онбординг

Ревизия 2 после ревью: условия завершённости шагов walkthrough переведены с состояния настроек на команды; из состава первого релиза убраны кэш и favicon (этап 07); проверка Cursor перенесена в этап 01.

Цель: человек, установивший расширение впервые, за минуту понимает модель («корни → обход →
правила решают, что узел, что проект, что скрыто → действия открывают») и получает работающее дерево.

После этого этапа собирается **первый релиз `.vsix`**.

## Пакет 05-A. Пустое состояние

Файлы: вклад `viewsWelcome` в `package.json`, `l10n` строки.

- Дерево без настроенных корней показывает не пустоту, а текст с двумя кнопками: «Add Root…» и
  «Как это работает» (открывает walkthrough);
- отдельное пустое состояние для случая «корни есть, но ни один проект не найден» — это почти всегда
  означает, что правила не подходят под структуру каталогов, и подсказка должна вести в правила, а
  не в добавление корней. Различить эти два состояния через `setContext`.

DoD: оба пустых состояния воспроизводятся и ведут в нужное место.

## Пакет 05-B. Walkthrough

Файлы: вклад `walkthroughs` в `package.json`, `media/walkthrough/*.svg|png`, `l10n`.

Шаги (каждый с картинкой и кнопкой-командой, каждый с условием завершённости):
1. **Выберите корни** — что такое корень, почему их может быть несколько. Кнопка запускает визард.
   Шаг отмечается выполненным через `onContext:projectsTree.hasRoots` (факт 21): расширение само
   ставит этот context key, когда корней стало больше нуля. `onSettingChanged` для этого не годится —
   он срабатывает на любое изменение настройки, а не на «значение непустое»; в ревизии 2 шаг
   завершался по факту запуска команды, что противоречило собственному DoD пакета;
2. **Как определяется проект** — модель правил, приоритетный список, дефолтный набор. Кнопка:
   открыть правила;
3. **Выделение важных папок** — зачем и как; пример правила по глубине. Про внешний вид сказано
   точно и без обещаний: подсветка метки, цвет и бейдж (до двух символов); цвет и бейдж пользователь
   может выключить настройками Explorer, а подсветка метки занимает тот же канал, что подсветка
   встроенного поиска. Жирного шрифта в стабильном API нет;
4. **Действия** — основное и альтернативные, пример с терминалом;
5. **Где живёт дерево** — три режима размещения и команда быстрого выбора.

Решение: используем нативный `contributes.walkthroughs`, а не свой webview. Причина — он встроен в
«Get Started», переоткрывается пользователем сам, поддерживает отметки о выполнении и не требует
поддержки собственного UI. Картинки должны иметь тёмный и светлый вариант.

DoD: walkthrough открывается при первой установке и вручную через палитру; первый шаг отмечается
выполненным по появлению корней (через context key), а не по клику по кнопке; отмена визарда шаг не
отмечает.

## Пакет 05-C. Визард выбора корней

Файлы: `src/editor/onboarding/{rootsWizard.ts,rootSuggestions.ts}`.

Визард (последовательность QuickPick/диалогов, не webview):
1. предложить кандидатов в корни — эвристика: каталоги в `$HOME`, содержащие несколько папок с
   `.git`/`.idea` на первом-втором уровне (у пользователя это `~/PhpstormProjects`), плюс папки уже
   открытых workspace;
2. дать выбрать несколько (multi-select QuickPick), с показом числа найденных проектов рядом с
   кандидатом;
3. предложить готовые предустановки правил на выбор — например «выделять первый уровень» для
   структуры вида `roots/{домен}/{проект}`;
4. показать превью результата перед записью в настройки.

Эвристика поиска кандидатов ограничена по глубине и времени: она не должна обходить весь `$HOME`.

Граничные случаи: `$HOME` без подходящих каталогов (визард сразу предлагает выбрать вручную); отказ
на любом шаге не записывает ничего; повторный запуск визарда при уже настроенных корнях — добавляет,
а не затирает.

DoD: на реальной машине визард предлагает `~/PhpstormProjects` в кандидатах; отмена ничего не пишет.

## Пакет 05-D. Первый релиз

- прогон `pnpm check` целиком;
- ручная проверка в VS Code и в Cursor: онбординг, дерево, действия. Базовая совместимость с Cursor
  подтверждена ещё в 01-D на заглушке, здесь проверяется функциональность целиком;
- README с описанием возможностей, скриншотами и таблицей настроек;
- тег, релиз с `.vsix`.

DoD: `.vsix` установлен на живой машине из релиза, дерево работает на настоящих
`~/PhpstormProjects`; совместимость с Cursor подтверждена на полном наборе функций; README содержит
раздел совместимости и явно называет, что кэша, реактивности и favicon в этом релизе нет (этап 07).

## Тестовый план этапа

Unit: эвристика кандидатов в корни на фейковой ФС; различение двух пустых состояний.
Интеграционные: условия завершённости шагов walkthrough; отмена визарда не меняет настроек.
Ручные: полный путь нового пользователя от установки до открытого проекта — в двух редакторах.
