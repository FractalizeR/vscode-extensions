## Refuted

| id | title | причина |
|---|---|---|
| qwen-02 | `HighlightSpec.icon` молча подменяется иконкой файловой темы, потому что `resourceUri` задаётся всегда | Отклонено фасилитатором вопреки собственной пометке Qwen `confirmed`. Официальный `vscode.d.ts` (`TreeItem.iconPath`) и исходник `src/vs/workbench/browser/parts/views/treeView.ts` (метод `hasIcon`, комментарий: «`file` and `folder` ThemeIcons defer to the file icon theme only when the item has a resource. Any other ThemeIcon … is always rendered as a codicon … regardless of the file icon theme») показывают: под приоритет файловой темы попадают только специальные иконки `ThemeIcon.File`/`ThemeIcon.Folder`; произвольный кастомный `ThemeIcon` (которым и должен быть `HighlightSpec.icon`, например `new ThemeIcon('star')`) всегда рендерится как заданный кодикон независимо от `resourceUri` и файловой темы (см. также `shouldHideResourceLabelIcon`, которая скрывает иконку файловой темы в пользу такого `ThemeIcon`). Канал `HighlightSpec.icon` не мёртв. |
| qwen-10 | Обоснование «без `resourceUri` не работает `FileDecorationProvider`» неточно: провайдер вызывается и по `id` элемента | Отклонено фасилитатором вопреки собственной пометке Qwen `confirmed`. В `treeView.ts` (метод рендера элемента) декорации (`fileDecorations`) запрашиваются только через `resourceLabel.setResource(...)` в ветке, где есть `resource` (`node.resourceUri`); в ветке без ресурса (`else`) вызывается `setResource({ name, description }, { hideIcon: true, ... })` без параметра `fileDecorations` вовсе — запроса декорации по `id`/`handle` элемента в этом пути нет. Формулировка плана «без `resourceUri` не работает `FileDecorationProvider`» по факту рендера дерева верна; предложенное Qwen уточнение не подтверждается источником, на который он сам сослался. |
