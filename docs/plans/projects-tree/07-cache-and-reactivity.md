# Этап 07. Кэш, фоновая перепроверка, favicon, реактивность

Вынесено из первого релиза по итогам round 01 ревью: эти четыре темы дали пять дефектов
(`refresh`-no-op, самопротиворечивый DoD кэша, отсутствие отмены у конкурирующих обходов,
неинвалидируемый отрицательный кэш favicon, нерешённая реактивность), потому что вводились как
оптимизации без контрактов. Здесь они вводятся вместе с контрактами.

Ревизия 3: пакет отмены и поколений переехал отсюда в этап 02 — он нужен первому релизу (сбор
списка проектов и эвристика визарда обязаны прерываться). Здесь остаётся то, что действительно
относится ко второму релизу.

Предпосылки из первого релиза: `NodeRegistry` с каноническим элементом на `NodeKey` (03-A) — без
него фоновое обновление было бы молчаливым no-op (факт 4); порт отмены и поколения (02-C).

## Пакет 07-A. Кэш между сессиями

Файлы: `src/projects/discovery/cache.ts`.

- снимок дерева, сериализуемый в JSON; расположение задаёт адаптер (`globalStorageUri`), ядро
  получает порт;
- **ключ кэша включает все входы дерева**: хеш файла правил, список корней с их `descend`,
  `maxDepth`, версию формата. Ревизия 2 включала только правила, из-за чего смена `maxDepth` или
  добавление корня оставляли кэш действительным;
- несовпадение версии формата — молча выбросить;
- **кэш — подсказка для мгновенной отрисовки, не истина.** `mtime` каталога не меняется при правках
  внутри вложенных файлов. DoD прежней ревизии («повторный обход не читает ФС для неизменившихся
  узлов») был самопротиворечив: проверка `mtime` и есть чтение ФС. Правильная формулировка: кэш
  отрисовывается без чтения ФС, а перепроверка идёт фоном и обновляется через `NodeRegistry`.

DoD: дерево отрисовывается из кэша без единого вызова порта ФС; фоновая перепроверка обновляет
ветку (интеграционный тест); битый JSON и кэш чужой версии не ломают старт.

## Пакет 07-B. Реактивность

Файлы: `src/editor/treeView/watcher.ts`.

- `FileSystemWatcher` через `RelativePattern` с `Uri` каталога корня — наблюдение **вне воркспейса**
  поддерживается, в том числе рекурсивное (факт 14). Это не самоочевидно: корни ProjectsTree по
  определению лежат вне открытой папки;
- наблюдаются верхние уровни корней. Глубокий рекурсивный watcher на дерево в сотни проектов не
  ставится — цена наблюдения выше выигрыша;
- события дебаунсятся и схлопываются в обновление ветки, а не дерева целиком;
- ручной Refresh остаётся: watcher не покрывает сетевые монтирования и изменения вне корней.

DoD: создание нового проекта в наблюдаемом каталоге появляется в дереве без ручного обновления;
массовое изменение (клонирование десятков репозиториев) не приводит к шторму обновлений.

## Пакет 07-C. Favicon как иконка проекта

Файлы: `src/editor/treeView/favicon.ts`.

- поиск favicon в подкаталогах из настройки (перенос `faviconWebRoots`/`faviconMaxDepth`
  прототипа), только для видимых узлов;
- **отрицательный результат кэшируется вместе с положительным и инвалидируется так же** — по
  поколению и хешу правил. Иначе добавленный в проект favicon не появится никогда;
- порог глубины прототипа (10) не переносится механически: он пересчитывается под реальную
  структуру web-корней, иначе поиск обходит проект целиком;
- изображение берётся из чужого репозитория. Ограничения: размер файла, допустимые форматы,
  отсутствие обращений к сети.

DoD: проект с `public/favicon.ico` показывается со своей иконкой; добавленный позже favicon
появляется после перепроверки; проект без favicon не задерживает отрисовку.

## Тестовый план этапа

Unit: ключ кэша от всех входов (правила, корни, `maxDepth`, версия) — по тесту на каждый вход;
инвалидация отрицательного кэша favicon.
Интеграционные: отрисовка из кэша без чтения ФС; фоновое обновление ветки; watcher на создание
каталога; дебаунс при массовых изменениях.
