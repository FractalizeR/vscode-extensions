Ревьюеры: `claude` (14 находок + 3 refuted, 5 HIGH), `codex` (14 находок, 5 HIGH, все confirmed).
28 находок → 21 различная проблема после дедупликации.

**Раунд оправдал себя дважды.** Во-первых, найдены дефекты, ломающие смысл фичи: стратегия
сабмодулей вообще не подключена к обходу, а сабмодульные узлы не могут стать проектами.
Во-вторых — и это важнее — три из десяти HIGH внесены **формулировками оркестратора**, а не
исполнителями: моим требованием zero-or-more для `**`, моим DoD «ни одного чтения каталога» и моим
недосмотром шва между пакетами.

## Проверено оркестратором независимо

| утверждение | вердикт | как проверено |
|---|---|---|
| Одиночный `\r` принимается в подстановке | **подтверждено** | `render('cd ${name}', …'a\rwhoami'…, zsh)` → `cd 'a\rwhoami'`; `\n` и `\r\n` отвергаются |
| `**` теряет границу сегмента | **подтверждено** | `libs/**/src` матчит `libsX/src` и `libs-extra/a/src`; `a/**/b` матчит `aXX/b` |
| Сабмодульные узлы не могут стать проектами | **подтверждено** | `descend.ts` классифицирует с `entries: []`, дефолтное правило проекта — `hasChild(['.git','.idea'])` |
| `childrenOfProject` не вызывается из production | **подтверждено** | grep по `src` без тестов: только определение, комментарий и реэкспорт |

## Группировка по механизму

### M1. Требования оркестратора, закрепившие дефект

Три HIGH, и все три — следствие моих формулировок, а не ошибок исполнителей:

- **`**` без границы сегмента.** Я потребовал заменить one-or-more на стандартную zero-or-more
  семантику. При переделке `libs(?:/.*)?/src` стало `libs(?:.*/)?src`, и соседний литеральный
  сегмент склеился без разделителя. Тест написали на положительный случай (`libs/src` матчится), а
  на отрицательный (`libsX/src` не должен) — нет.
- **Сабмодуль не проект.** Мой DoD требовал «не читает ни одного каталога внутри проекта», и
  требование эффективности задавило функциональность: без чтения каталога `hasChild('.git')` не
  сработает никогда. Тест со счётчиком закрепил неверный инвариант.
- **Мёртвая стратегия.** Я принимал пакеты по одному, а шов 02-D ↔ 02-E не проверил. `descend.ts`
  не мог тронуть `walker.ts` по изоляции, `walker.ts` был сдан до появления `descend.ts`.

**Решение:** DoD переформулировать так, чтобы он выражал инвариант, а не его прокси: «обход не
идёт рекурсивно внутрь проекта; читается ровно один каталог на объявленный сабмодуль». Требование
границ сегмента внести в план явно (glob совпадает по целым сегментам). Приёмка пакета получает
обязательный пункт: **вызов из production-кода существует** — grep по символу вне тестов.

### M2. Диагностика теряется, а падает позже и в другом месте

- некомпилируемая регулярка: `validateRules` возвращает 0 диагностик, затем `SyntaxError` роняет
  весь обход (claude-06 = codex-02);
- ReDoS-эвристика пропускает перекрывающуюся альтернацию `(a|aa)+`, и это не диагностика, а
  зависание extension host (claude-03 = codex-11);
- парсер `.gitmodules` объявляет битым файл, который `git` принимает (claude-11 = codex-08).

Общий механизм: валидация проверяет форму, но не то, что значение пригодно к использованию.
**Решение:** валидация обязана компилировать регулярку и возвращать диагностику вместо исключения;
эвристику дополнить проверкой перекрывающихся ветвей альтернации под квантором; парсер сверить с
`git config --list --file` на живом git и сузить отказы до действительно невалидного.

### M3. Отмена не отменяет уже начатое

`Promise.all` над детьми ставит все чтения сразу, и `throwIfCancelled` между итерациями их не
останавливает (codex-04). Отмена работает как «не начинать новые», а не «прекратить».
**Решение:** проверка отмены внутри задачи-обёртки каждого чтения, а не только в цикле
планирования; тест на счётчик после отмены при уже запущенной пачке.

### M4. Проверка пути лексическая, а угроза файловая

`resolveSegments` отбивает `../`, абсолютный и windows-абсолютный путь, но не видит symlink:
объявленный `path = link`, где `link` → `../../etc`, проходит (codex-05).
**Решение:** после лексической проверки сверять `identity()` цели с поддеревом проекта, либо
отказывать сабмодулю, чей путь — симлинк.

### M5. Тесты, не проверяющие заявленное

- тест заявляет `stopDescend`, но не задаёт его (codex-09) — то есть остановка обхода не покрыта;
- тесты квотирования проходят при неполном экранировании (`replaceAll`→`replace`) — round-trip
  через собственный `unquote` тавтологичен (claude-02);
- три `index.test.ts` существуют ради knip, а не как контракт поверхности (claude-10).

**Решение:** тест на `stopDescend` переписать так, чтобы он падал без поля; квотирование проверять
на многократном вхождении спецсимвола и явными ожидаемыми строками, а не только round-trip;
барьерные тесты либо превратить в контракт (проверять форму экспортируемого, а не факт экспорта),
либо снять вместе с настройкой knip, которая их требует.

### M6. Контракты, не покрывающие свои же сценарии

- в каноническом файле правил **негде объявить действия**, хотя правила ссылаются на
  `primaryAction` (codex-06);
- рендер не охватывает аргументы `command` и `process` (codex-07), хотя подстановки там те же;
- `badge` считается в UTF-16 code units, а VS Code — по code points (codex-13);
- cmd-квотирование `%` взято из batch-правил, а терминал интерактивный (codex-01 = claude-12).
